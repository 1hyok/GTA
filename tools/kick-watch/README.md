# 방치 퇴장 원인 확인

기록기는 키·마우스·전면화·세션 변경을 하지 않는다. 기존 `GTA Kick Watch` 예약 작업과 같은 진입점을 사용한다. `Main.ahk` 재시작 없이 기록기만 교체할 수 있다.

## 남기는 증거

`%USERPROFILE%\gta-kick\`에 다음 기록을 저장한다.

| 기록 | 확인할 수 있는 사실 |
|---|---|
| `fg.log` | 1초 간격 관찰에서 확인된 전경 프로그램 변경 |
| `events.log`, `shots\` | 런처의 세션 변경 통지와 2·15·45초 뒤 전체 화면. 퇴장 문구와 일반 세션 이동을 구분 |
| `observations.jsonl` | 5초 간격의 전경 PID/HWND, 커서 좌표와 커서 아래 창, Windows 세션의 마지막 입력 시각. AFK 로그에 새로 추가된 줄과 관찰 시각 |
| `afk-shots\` | AFK 입력 로그를 관찰하기 전 최근 표본(10초 이내만), 관찰 직후, 2초 뒤의 GTA 영역. 세션 변경 통지 직전 표본 3장 |

GTA가 전경일 때만 게임 클라이언트 영역의 표시된 픽셀을 캡처한다. 가림·메뉴·오버레이도 그대로 찍히며 게임 내부 화면을 추출하지 않는다. 평소에는 최근 PNG 3장만 메모리에 보관하고 사건 때 저장한다. AFK PNG는 최근 90장, 기존 사건 전체 화면은 별도로 최근 120장을 유지한다. 각 로그는 2 MiB에서 직전 파일 하나를 남기고 순환한다. 기록기 시작 시 코드·설정 파일의 디스크 해시를 남긴다. 이 해시는 실행 중인 AHK가 로드한 버전을 증명하지 않는다.

AFK 로그를 읽지 못하거나 캡처가 실패하면 오류를 기록하고 기존 세션 감시는 계속한다. `before_age_s`와 표본 시각을 보고 오래되거나 누락된 화면을 구분한다. `before`는 AFK 로그 관찰 전 표본이며 입력 함수의 바로 전 프레임이라는 뜻이 아니다.

## 증거의 한계

- `mouse pulse`는 함수 실행 기록이다. 게임의 입력 수신이나 방치 타이머 초기화를 확인한 결과가 아니다.
- `GetLastInputInfo`는 Windows 세션의 입력 시각이다. 게임별 입력 시각이 아니며 다른 프로그램·사용자 입력도 포함한다.
- 현재 마우스 방식은 상대 이동 `+2`, 100ms 대기, `-2`다. 상대 이동값은 정확히 2픽셀을 보장하지 않는다. 전후 커서나 화면이 같아도 그 사이 움직임이 없었다고 단정할 수 없다.
- 5초 표본은 100ms 이동을 포착하는 고속 촬영이 아니다. 화면 종류·포커스·퇴장 경고의 전후 맥락을 보존한다. 게임이 입력에 반응했는지를 직접 보려면 별도 고속 캡처 또는 실제 퇴장 경고 변화가 필요하다.

Windows API의 반환값과 관측 범위는 [mouse_event](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-mouse_event), [GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo)를 따른다.

## 원인을 분리하는 실제 시험

게임 조작을 맡긴 구간에서만 진행한다. 현재 플레이·매크로와 동시에 시험하지 않는다.

1. 같은 초대 전용 세션·장소·화면·입력 간격을 고정한다. 보스 등록을 해제하고 다른 매크로·컨트롤러·사용자 입력이 섞이는 회차를 제외한다. 설정 파일 해시와 실행한 코드 버전을 남긴다.
2. 기존 마우스 방식의 관찰 구간을 먼저 기록한다. 정상 입력으로 시작 시각을 분명히 한 뒤 시험 입력만 허용한다. 기존 15분 퇴장 관측보다 긴 20분을 초기 관찰 구간으로 사용하고 시작·끝 화면과 실제 퇴장 시각을 남긴다.
3. 같은 화면에서 안전하게 사용할 수 있는 키 입력으로 비교한다. W/S가 MCT 메뉴 선택을 바꾸면 화면 상태가 달라지므로 그 회차를 동일 조건 비교로 세지 않는다. 일반 프리모드와 MCT를 별도 조건으로 다룬다.
4. 전경을 유지하는 경우와 다른 창을 사용하는 경우를 분리한다. 포커스와 입력 종류를 동시에 바꾸지 않는다. 동일 조건의 반복과 순서 교차로 우연한 연결 종료·세션 차이를 확인한다.
5. 퇴장 문구가 `idle too long`인지 확인한다. 마우스에서만 반복 퇴장하고 비교 입력에서는 유지되면 해당 화면에서 현재 마우스 방식의 보호 실패를 재현한 것이다. 다른 창을 사용할 때만 실패하면 포커스 조건을 원인 범위로 좁힌다. 한 번 유지된 결과로 장시간 보호를 보장하지 않는다.

무입력 대조가 필요하면 재접속을 포함한 해당 시험 구간을 별도로 맡긴 뒤 진행한다. 기존 관측에 없는 게임 내부 정책이나 모든 화면에 대한 결과를 추측하지 않는다. 각 시험은 입력·화면·포커스 조건과 성공·실패·중단 사유를 함께 남긴다.

## 입력 없는 검사

```powershell
python -m unittest discover -s tools/kick-watch -p 'test_*.py' -v
python tools/kick-watch/kick-watch.pyw --once
```

회귀 검사는 로그 분할·교체·접근 실패 복구, JSON 기록, 화면 보존 한도, 배경 화면 미캡처, AFK 입력 전후 표본·지연 캡처를 확인한다. `--once`는 현재 상태와 화면만 저장한다. 두 검사는 실제 접속 유지 시험을 대신하지 않는다.
